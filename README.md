# textula — детали города

Карта визуальных находок Тулы: фактуры стен, старинные вывески, узоры решёток.
Живёт на [textula.ru](https://textula.ru).

Кто угодно может добавить точку с фотографией — она попадает в очередь
модерации и появляется на карте после одобрения. Есть игра «угадай локацию»:
десять раундов, фотография и карта, очки за близость и скорость ответа.

## Как устроено

Сайт статический и лежит на GitHub Pages: корень репозитория — это корень
сайта, сборки нет. Поэтому `index.html`, `app.js`, `styles.css`, `sw.js` и
иконки лежат прямо в корне, а не в `src/` — их отдаёт тот же путь, по которому
они запрошены.

Данные — в Supabase: таблицы `details` (точки), `notes` (описания) и `photos`
(дополнительные снимки), плюс бакет `photos` для файлов. Запись из браузера
разрешена только со статусом `pending`; изменять и удалять анонимный ключ не
может ничего — этим занимается edge-функция под service-role ключом.

```
index.html          разметка, подключает styles.css и app.js
styles.css          всё оформление
app.js              всё поведение: карта, формы, модерация, игра
sw.js               офлайн-кэш
assets/             иконки, картинка для превью ссылок, анимация логотипа
vendor/             Leaflet, markercluster, lottie, EmailJS, шрифты — свои копии,
                    чтобы сайт не зависел от чужих CDN и работал офлайн
d/                  сгенерированные страницы находок (см. ниже)
scripts/            генератор страниц и разовый скрипт превью
supabase/           миграции базы и edge-функции
tests/              проверки в headless-браузере
```

### Страницы находок

`d/<id>/index.html` для каждой одобренной точки собирает `npm run seo` —
это нужно поисковикам, которые не выполняют скрипты. Страницы лежат в
репозитории, потому что без сборки Pages их взять больше неоткуда. Генератор
каждый раз сносит каталог целиком и пишет заново, так что удалённые точки не
оставляют мусора. Раз в сутки то же самое делает GitHub Action
(`.github/workflows/seo.yml`) — новые точки попадают в поиск сами.

### Модерация и админка

Пароль проверяет функция `admin-login`, она же выдаёт подписанный токен на
8 часов. Все операции — `admin-action`, она проверяет подпись и ходит в базу
под service-role ключом. В браузере токен лежит в `sessionStorage`; сам по себе
он ничего не открывает, кроме вызовов этой функции.

Секреты задаются в проекте Supabase, в репозитории их нет:

| Переменная | Зачем |
|---|---|
| `ADMIN_PASSWORD` | пароль входа в админку |
| `ADMIN_TOKEN_SECRET` | ключ подписи токенов; если не задан, подписывается паролем |

### Фотографии

При загрузке рядом с оригиналом сохраняется превью шириной 480 px в
`photos/thumbs/` с тем же именем, а его адрес — в `thumb_url`. Превью уходит в
маркеры, поиск, модерацию и список находок; полный размер — только в карточку
точки, на страницу находки и в игру. Разница ощутимая: карта грузила около
30 МБ снимков, стала — меньше мегабайта.

## Работа с проектом

```bash
npm install
npm run dev     # локальный сервер на http://localhost:5173
npm test        # проверки в headless-браузере
npm run seo     # пересобрать страницы находок и sitemap
```

Проверки ничего не записывают: в базу не пишут, в бакет не загружают
(отправка подменяется), читают только публичные данные. Можно прогнать по
боевому сайту — `BASE=https://textula.ru/ npm test` — или один набор:
`npm test game` (`layout`, `game`, `photos`, `seo`).

### База данных

```bash
supabase db push                      # применить миграции
supabase functions deploy admin-login
supabase functions deploy admin-action
```

Миграции лежат в `supabase/migrations/` и применяются по порядку. Схема таблиц
описана в `20260821120000_schema_and_limits.sql`, политики доступа — в
`20260810120000_lockdown_rls.sql`.

## Что стоит знать, прежде чем менять

- **Ключ Supabase в коде публичный** (`sb_publishable_…`) — так и задумано,
  доступ ограничивают политики RLS, а не секретность ключа. Он продублирован в
  `app.js` и двух скриптах: при ротации поменять во всех трёх.
- **Даты считаются по Туле**, а не по часовому поясу читателя или машины
  сборки — иначе одна и та же находка показывала разные числа на карточке и на
  своей странице.
- **Игра берёт только точки в пределах 50 км от центра города**: находка из
  другого города растягивала обзор раунда на пол-страны и всё равно не
  угадывалась.
- **Высота шапки не постоянна** — она уезжает в переменную `--header-h`, от
  которой считаются строка поиска, фильтры и панель игры. Не прописывайте под
  шапкой отступы числом.
- **Разметка Schema.org экранируется** через `jsonLdBlock`: `JSON.stringify` не
  трогает `</script>`, и название находки с такой строкой выполнялось бы как код.
