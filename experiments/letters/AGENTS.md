# Пополнение коллекции букв

- Перед пополнением прочитай `README.md` и `processed-photos.json`.
- Перед любой работой с коллекцией прочитай `editor-edits.json` и, если существует, `editor-history.jsonl`: это сохранённые пользователем исправления. Они уже применены к `manifest-all.json`, `edited/` и ZIP. Не сбрасывай их, не меняй стабильные ID вариантов. `manifest-base.json` нужен для восстановления исходной разметки; `build_collection.py` автоматически накладывает исправления поверх новой сборки.
- Для интерфейса с сохранением запускай `python3 experiments/letters/serve.py --port 5173`. Пользовательские правки записываются непосредственно в проект после нажатия «Сохранить в коллекцию». Скрытие обратимо и не удаляет файлы; скрытые варианты не включаются в ZIP.
- На macOS есть `start-editor.command` для повторного запуска; он использует постоянное окружение `.editor-venv`. Снимок редактора и правок ревизии 123 сохранён в `editor-snapshots/revision-0123.zip`; актуальны всегда рабочие `editor-edits.json` и `editor-history.jsonl`, а не этот снимок.
- `play.html` — отдельный тестовый конструктор надписей. Он читает актуальную коллекцию, исключает скрытые варианты и не изменяет редакторские данные. Не подменяй исправленные пользовательские рамки исходными при доработке конструктора.
- Выполни `python3 experiments/letters/check_new_photos.py`: он читает одобренные обложки и дополнительные фотографии, формирует `pending-photos.json` и не меняет реестр.
- Обрабатывай только фотографии из очереди. Уже просмотренные снимки без читаемых букв и неоднозначные снимки тоже считаются обработанными; повторно их не просматривай без запроса пользователя.
- Учитывай замену обложки у существующей находки: сравнивай URL фотографии, а не только ID находки. Несколько фотографий одной находки — отдельные источники. SHA-256 в реестре фиксирует точные байты просмотренного файла; проверка по URL не обнаруживает удалённую замену файла под тем же URL.
- Записывай фото в реестр только после реального просмотра и завершения нарезки/проверки. Сохраняй source_id, photo_url, local_file, sha256, reviewed_at, status, crop_count, crop_ids, note. Для фото без букв ставь crop_count: 0 и указывай причину.
- Существующий `all-sources.json` имеет стабильный порядок: `selections.py` ссылается на индексы. Не переставляй старые записи; новые добавляй в конец после просмотра. Для дополнительных фотографий используй отдельный уникальный ID исходника и сохраняй связь с ID находки.
- Не запускай `build.py` для общей коллекции: это генератор первого эксперимента. Используй `build_collection.py` после обновления разметки и реестра.
- Не удаляй никакие файлы без разрешения пользователя.

- Редактор доступен после входа в админку главной страницы (меню ☰ → Админ → Редактор букв в панели модерации). Не возвращай ссылки на него в публичный конструктор. API состояния и сохранения требует X-Textula-Admin с действующим токеном, проверяемым через admin-action.
- Фильтр «Только чёткие» использует `letter-quality.json` и совпадение ID + имени кропа. Не подставляй размытые буквы при отсутствии чёткой. Классификация пересчитывается через `build_letter_quality.py` при сохранении и пересборке; исходные буквы и пользовательские правки не изменяются.
